# 映答当前问题与改进优先级

检查日期：2026-10-22。依据当前源码、既有运行截图、测试记录以及本轮只读 API 核验；不把界面效果、提示词要求或依赖存在视为功能已经完成。

## P0：账号安全和管理权限

1. **密码明文存储与校验。** 上轮在独立测试账号上直接查询 MySQL 已确认，`UserServiceImpl.login` 仍按 username/password 等值查询。需要密码哈希、旧账号迁移及修改密码时验证原密码；当前资料编辑页不提供密码变更。
2. **旧账号接口越权读取。** 本轮用非管理员 `lqx_demo` 只读取合成测试账号，实测可通过 `/users/actual/{其他测试用户名}` 读取对方资料，也可以调用 `/users/page` 列出测试账号。新 `/users/me` 的边界正确，但未覆盖这些旧接口。需要统一为本人资料接口，并对用户列表、管理员查看他人资料添加后端角色校验。
3. **管理操作缺少完整角色隔离。** 普通账号实测能读取 `/ai-properties` 配置列表（响应按既有逻辑脱敏，不将其描述为明文密钥泄漏）。源码中题库写入、删除、联网扩充、知识文档删除/重建索引、模型配置写入未见明确管理员校验；知识库服务也未按上传人隔离。需要定义公共题库、平台知识库和个人资料的边界，管理写操作在后端执行角色校验。本轮没有执行删除、扩充、重建或模型配置修改来试验权限。

运行证据：`.research/review-20261022/checks.json`。当前普通账号角色为 false，跨测试用户读取与配置读取均返回成功。当前管理员记录数为 0 是前一轮实测结果，不应自动提升账号权限来掩盖问题。

## P1：题库真正进入面试与复盘

4. **逐题来源还没有形成完整链路。** `DirectInterviewAi` 要求输出 `source_ids`，但源码检索未发现后续逐题持久化及报告消费；现有执行面板展示的是某次检索命中列表，不能证明每道生成题实际依据哪条资料。应把题目、题库 ID、知识片段/页码、改编性质关联保存，并在报告中点击回到参考资料。
5. **评分需要校准与报告数据闭环。** 已观察到真实报告中雷达维度为空、综合分标记估算值。应明确各维度生成与计算规则、缺失时的展示逻辑、主问题与追问如何汇总；用固定答案样本验证正确回答、部分正确、跑题及表达较短等情况。既有流程/结构测试不足以单独证明评分可靠。
6. **学习闭环不完整。** 可出题、回答、评分、出报告，但还应让报告里的薄弱点直接生成下一次练习入口，沉淀错题/收藏与岗位目标，支持同一知识点再次练习及跨场次比较。新增功能应围绕已有题目、问答与报告数据组织。
7. **执行可视化与实际智能体编排需要对应。** 已有 Java 执行步骤和真实工具耗时；直连流程仍主要按阶段切换同一模型调用的职责。下一步应明确简历分析、出题、评分、追问、报告的输入输出、任务交接、工具调用和回退条件，让可视化反映真实协作关系。不能把阶段连线本身描述为独立智能体已实现自主协作。

## P2：体验、性能与交付

8. **性能与空状态。** MiSans VF 约 11.9 MB，两张新增透明 PNG 共约 2.66 MB。可以做字体分片、图像格式优化与缓存；测试较慢网络下的字体回退及加载过程。报告无维度数据时应有更紧凑、有解释的空状态，长反馈与检索失败也需要清晰的操作出口。
9. **多岗位深度与资料呈现。** 本轮实测题库 136 题、知识文档 9 份、知识块 2930；各新增岗位题量仍有限。应按岗位与级别建立覆盖矩阵，优先补薄弱方向和评分标准，并优化知识资料的标题、来源与阅读入口。数量不是面试质量的替代指标。
10. **课程交付仍有硬性待办。** 指派 IP 范围已确认，但实际主机部署、正式报告题目与提交格式仍待落实；LaTeX 模板不能替代教师要求的 Word 目录域更新。应在确定部署与交付要求后验证新环境启动、保留备份和实际运行证据，并记录开源来源及自主修改。

## 建议顺序

先修密码与旧接口权限，再打通逐题来源和报告数据；随后完善薄弱点练习闭环与实际智能体任务协作。视觉细节和资源加载继续随页面完善，课程 IP 与交付准备并行推进。
