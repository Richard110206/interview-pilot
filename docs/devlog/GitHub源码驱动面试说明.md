# GitHub 源码驱动面试

2026-10-22。用户确认通过现有对话发送仓库链接，不增加独立提交页面、表单或 GitHub 上传按钮。

## 用法

进入面试室，在原输入框发送，例如：

```text
我希望练习业务接口、数据库访问和事务，请结合这个公开示例项目提问：
https://github.com/spring-projects/spring-petclinic
```

可以发送仓库首页、`/tree/分支/目录`、`/blob/分支/文件`，并在同一条消息说明模块。一次一个仓库。目录/文件链接解析真实分支引用，支持带斜杠的分支名。仓库不能证明发送者是作者，系统将其视为项目学习资料。

- 准备阶段：自动创建面试会话、后台读取源码、索引片段，再经原有提题链路生成问题。不要求同时提供 PDF，也不生成简历得分。
- 面试阶段：链接消息作为资料，不提交评分，不推进当前题；后续评分和追问可读取本场相关源码。已经生成的主问题保持原样。
- 处理中：进度作为对话消息显示。刷新或重新进入同一会话后继续读取后台状态并恢复当前问题。
- 失败：在同一输入框重新发送链接。完成后重复相同消息会复用当前导入。
- 报告：点击“源码 · 文件:行号”查看当时快照、固定提交版本、原始行号，也可打开 GitHub 对应版本。收藏与专项再练习保留代码来源，评分请求带入这些来源快照。

## 模型与工具分工

当前接入的普通 DeepSeek Chat Completions 请求不会因提示词里出现 URL 自动获取仓库。Java 负责实际读取与检索，模型接收受限代码上下文后分析、出题、评分和追问。无需安装额外浏览器、Git CLI、MCP 服务器或 GitHub 插件。

实现新增 `GitHubRepositoryClient`、`InterviewProjectStore`、`InterviewProjectImportService`。它们是平台自己的工具服务；本版本采用服务端确定的调用流程，没有把 GitHub 操作伪装成模型自行执行的 function call。若后续使用模型 Tool Calls，实际函数仍须由后端执行，参见 [DeepSeek 官方工具调用说明](https://api-docs.deepseek.com/guides/tool_calls/)。

仓库首页优先使用 GitHub REST 获取仓库与提交元数据；匿名 REST 限流时，回退公开 Git smart HTTP 引用。目录/文件链接直接通过公开引用解析分支与路径。随后按 commit SHA 从 GitHub codeload 读取 ZIP。原理参见 [GitHub 源码快照](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)、[Git HTTP 协议](https://git-scm.com/docs/http-protocol/2.17.0)。版本不随主分支更新而改变。

## 存储与接口

MongoDB 新增 `interview_project_import`（会话最新导入与进度）、`interview_project_code`（用户/会话/导入版本隔离的代码片段）。不污染公共知识库，无新增 MySQL 迁移。逐题来源继续使用 `interview_question_evidence`，新增代码类型及仓库、commit、文件、行号、链接字段。

| 方法 | 路径，相对 `/api/xunzhi/v1` | 用途 |
|---|---|---|
| POST | `/interview/sessions/{id}/project/messages` | `{ "message": "包含链接的用户消息" }` |
| GET | `/interview/sessions/{id}/project` | 导入状态，尚未关联时 data 为 null |

接口先检查会话归属，终态会话不能追加导入。同会话活动任务拒绝不同材料并发导入；相同材料复用导入，任务领取通过 MongoDB 条件更新，重复调度不会执行第二次。重启中断的活动任务十分钟后可重试。后台两条工作线程、八个等待位置；模型提题仍经过原 session 重锁、AI Guard 和 singleflight，不改答题幂等和追问上限。

## 范围与限制

- 当前仅支持公开 GitHub 仓库。私有仓库需要另接只读授权，当前不收集聊天中的令牌。
- 只静态读取，不执行仓库代码、构建脚本或子模块。只访问固定 GitHub 官方主机，不跟随任意重定向；压缩包只在内存解析，不按归档路径写入磁盘。
- 下载最多20MB，展开最多80MB，最多10000个归档条目；单个入选文本最多256KB，选取最多120文件、200万字符，最多1600代码片段。超限或无法读取会明确提示，不声称完整分析整个仓库。
- 排除依赖、构建产物、二进制、`.env` 与明显凭据文件；可能的密钥赋值行隐藏，保留换行位置。这是基础过滤，不保证任意公开仓库均不含敏感信息。
- 当前按文件/行号窗口切片，结合关键词、技术词扩展、路径和生产/测试优先级检索。没有构建 AST 调用图、全量语义向量索引或运行验证。测试材料不当作生产方法内部实现的证据。
- 单次模型上下文最多选择8个片段、约18000字符，并限制同一文件数量。出题来源只接受本次实际检索到的片段 ID，源码面试没有真实代码引用则失败重试。
- 代码、README 与注释视为不可信材料，其指令不能修改模型角色与评分规则。相关代码片段会发送至已配置的模型服务用于分析。
- 代码片段与导入记录随本机 MongoDB 持久化。尚未增加项目删除或保留期限设置；后续如扩展私人仓库，应同时增加撤销授权、删除和保留策略。
