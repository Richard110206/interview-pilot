# 面试室界面与设备权限调整

日期：2026-10-20。用户要求重新加载摄像头、重新确认权限，并使用 frontend-design 技能降低界面的模板感。

## 已实施

- 面试室改为问答主区与准备侧栏。简历和摄像头进入固定侧栏，不再覆盖问答内容。手机端按纵向排列。
- 页面采用白色、灰蓝底色、深青主按钮；中文使用本机微软雅黑 UI 字体。保留真实的准备、问答、报告三个流程步骤，减少装饰性卡片、阴影和动效。
- 去掉没有岗位依据的“Java 高级开发工程师”标题。准备页显示简历入口和作答提示，问答、简历预览、构思板、评分数据仍连接原控制器。
- 摄像头默认关闭，点击后才请求权限；拒绝后显示中文恢复说明及“重新尝试”。重试会重新请求设备，成功状态由实际设备回调更新。
- 关闭摄像头、离开页面或取消待完成的申请会停止已取得的媒体轨道；避免开发 StrictMode 重复请求摄像头。只有摄像头实际就绪时才允许原有仪态采样逻辑运行。
- 预览仅显示实际摄像头状态，不再显示固定的“正在分析”。未开始时禁用作答、发送和结束面试，作答增加可点击的发送按钮。
- Vite 开发地址固定为 127.0.0.1:5173，端口被占用时明确失败，避免自动换端口导致访问另一站点的权限记录。开发服务已重新加载。

## 权限恢复

网页无法把浏览器已经保存的“禁止”直接改成“允许”。应在浏览器地址栏旁的站点设置中，允许摄像头或重置该站点权限，然后回到页面点击“重新尝试”。如果内置预览没有站点权限入口，可在 Chrome／Edge 打开同一地址再授权；不同浏览器的授权彼此独立。系统级阻止需要在 Windows 相机隐私设置中恢复。

刷新后摄像头仍默认关闭。点击“开启摄像头”才重新请求，不会因为重载页面自动打开设备。
