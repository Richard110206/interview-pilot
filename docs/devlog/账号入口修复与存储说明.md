# 管理账号入口与存储

2026-10-22。

## 已修复

侧栏用户菜单的“管理账号”原为未绑定事件或路由的空按钮。现已连接受登录保护的 `/account` 页面，并在跳转时关闭菜单。页面支持读取、修改姓名、手机号与邮箱，重置未保存内容，以及显示后端返回的账号角色。用户名用于登录，此处不修改；密码变更与管理员授权不属于本次资料编辑。

后端新增 GET/PUT `/api/xunzhi/v1/users/me`，以 `@CurrentUser` 解析 token 对应身份。更新请求只接收真实姓名、手机号、邮箱；提交其他用户名、密码或管理员字段不会改变这些属性。保存后从服务器重新读取并同步侧栏资料，刷新页面仍然保留。

## 实际存储位置

- 本机 MySQL：`127.0.0.1:13306`，数据库 `ai_meeting_lqx`。账号数据在 `t_user`，管理员标记在 `admin_permission`。
- Docker 数据卷：`lqx-ai-meeting_mysql-data`，挂载到 MySQL 容器 `/var/lib/mysql`。不是保存在浏览器内；关闭网页或重启应用不等于删除数据库数据。
- Redis：本机 `127.0.0.1:16379`，保存 token/登录会话及缓存。
- 浏览器：localStorage 保存登录 token。当前用户资料保存在前端运行时状态，最终来源仍为服务端数据库。
- 实测当前启用管理员角色记录为 0 条；“管理账号”是每个用户自己的资料入口，普通用户可以进入。此次没有提升任何账号权限。

## 已知限制

原项目的注册、登录仍沿用明文密码字段与等值校验。本次没有修改密码存储方案，也没有把密码暴露给资料接口；密码哈希迁移及密码修改流程需要单独完善。
